# 클릭형 MBTI 테스트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 구현 요청이 오면 이 세션에서 순서대로 진행한다.

**Goal:** 프로젝트 허브에서 들어가 질문의 답변을 클릭하고, 최종 MBTI 유형을 확인할 수 있는 작은 테스트를 만든다.

**Architecture:** 기존 Next.js 앱 안에 `/mbti`를 추가한다. 질문·선택지·결과를 정적 TypeScript 데이터로 정의하고, 클라이언트 컴포넌트 하나가 현재 질문과 이전 선택 경로를 관리한다. 허브의 기존 `PROJECTS` 배열에 카드 하나를 추가한다.

**Tech Stack:** 현재 설치된 Next.js 16, React 19, TypeScript, Tailwind CSS 4, Node.js 내장 assert.

**Spec:** 사용자 요청과 `mbti-flowchart.md`. 클릭 가능한 분기로 바꾸는 결정과 화면 요구사항은 아래에 정의한다. 이 문서는 구현 전 검토할 계획이며 제품 코드는 아직 변경하지 않는다.

## Global Constraints

- 경로는 `/mbti`, 허브 카드명은 `🧠 재미로 보는 MBTI`로 한다.
- 이미지의 분기 결과를 이용하며 E/I 등의 점수를 새로 계산하지 않는다.
- 시작 화면과 결과 화면에 `이미지 속 흐름도를 바탕으로 만든 재미용 테스트입니다. 정식 MBTI 검사가 아닙니다.`를 표시한다.
- 로그인, DB, API, 외부 서비스, 신규 의존성 없이 동작한다.
- 답변은 React 메모리에만 둔다. 새로고침하면 시작 화면으로 돌아간다.
- 기존 허브 카드와 다른 프로젝트의 동작은 유지한다.
- 모바일 우선, 기존 Tailwind 스타일과 다크 모드를 따른다.

## 사용 흐름과 화면

1. 허브 `/`에서 새 카드를 클릭하면 `/mbti` 시작 화면으로 이동한다.
2. 제목, 재미용 안내, `시작하기`를 보여준다. 상단 `프로젝트 허브` 링크는 항상 `/`로 이동한다.
3. 시작하면 질문 하나와 답변 버튼 2~3개를 보여준다. 답변 클릭 시 즉시 다음 질문 또는 결과로 이동한다.
4. 질문 중에는 `이전 질문`과 `처음부터`를 제공한다. 첫 질문의 이전 버튼은 비활성화한다.
5. 결과에는 MBTI 4글자를 크게 표시하고, 내가 선택한 질문·답변 목록과 `다시 하기`, `프로젝트 허브`를 제공한다.
6. `이전 질문`으로 되돌아간 뒤 다른 답을 고르면 기존 후속 경로를 버린다. 결과에서도 `이전 질문`으로 마지막 답을 바꿀 수 있다.

분기별 질문 수가 다르므로 고정된 총 문항 수나 퍼센트는 표시하지 않는다. 현재 `질문 N`만 표시한다. 결과별 장문 해설·이미지, 공유, 결과 저장은 첫 버전에서 제외한다.

## 원본을 클릭 가능한 분기로 바꾸는 기준

원본의 답변 박스는 버튼으로, 자동으로 이어지는 설명 박스는 버튼 문구 또는 결과 경로로 합친다. Mermaid를 실행 중 파싱하지 않는다.

앞서 변환한 Markdown은 일부 답변명과 연결선이 불완전하므로, 아래를 구현용 분기로 사용한다. 특히 감정 질문 주변의 겹친 연결선은 **설계상 해석**이며 원본의 정확한 복원을 보장하지 않는다.

| 질문 ID | 질문 | 선택지 → 다음 질문 또는 결과 |
| --- | --- | --- |
| start | 너 이상해? | 응 → social / 아니 → rules |
| social | 사회적으로 불안해? | 응 → logic / 아니 → bad |
| logic | 논리적이야? | 응 → emotion-logical / 아니 → emotion-other |
| emotion-logical | 감정적이야? | 응 → INFJ / 미친 듯이 울음 → INFP / 아니 → really |
| emotion-other | 감정적이야? | 응 → INFJ / 미친 듯이 울음 → INFP |
| really | 진짜로? | 돌로 된 심장에 대한 찰스 다윈 명언 → INTJ / 설명하기엔 좀 길어 → machines |
| machines | 기계 좋아해? | 완전 좋아 → ISTP / 괜찮네 → INTP |
| bad | 나쁜 놈이야? | 아니 → INFJ / 아마 그런 듯 → lazy |
| lazy | 게을러? | 아니 → ENTJ / ㅇㅇ → chakra |
| chakra | 차크라 믿어? | 개소리지 → ENTP / 명상 좀 더 해야겠어. 힘의 중심이 안 맞아 → ENFP |
| rules | 규칙은? | 어기라고 만들어진 것 → extreme / 사회가 원활하게 굴러가기 위해 필요한 것 → enforce / 짜증 나지만 않으면 괜찮아 → one-night |
| extreme | 익스트림 스포츠? | 존중 → ESTP / 차라리 마약을 하겠다 → quiet |
| quiet | 조용하게? | 아니 → ESFP / 응 → ISFP |
| enforce | 규칙을 강제한다면? | 소리 지르면서 → ESTJ / 소리 지르지는 않고 → ISTJ |
| one-night | 원나잇 어케 생각해? | ㄱㅊ네 → college / 아베 마리아를 40번 말함 → ISFJ |
| college | 대학 교육 받았어? | 젠더학 → ENFJ / 아니 → ESFJ |

`rules`의 마지막 선택지는 원본 이미지의 `짜증나지만 않으면 괜찮아`로 바로잡는다. `enforce`는 원본의 연속된 `강제할 거야? → 소리지르면서??`를 하나로 합친 질문이다. 이 두 보완과 감정 질문 해석은 `mbti-flowchart.md`에도 반영해 구현 데이터와 참고 문서의 차이를 남기지 않는다.

## Review Focus

- 누락된 분기 또는 순환 때문에 결과에 도달하지 못함: 모든 질문에서 모든 선택지를 순회해 검사한다.
- 16개 유형 중 일부가 도달 불가능함: 시작점에서 도달한 결과 집합이 정확히 16개인지 검사한다.
- 이전 답변을 바꿨는데 결과에 예전 경로가 남음: 재선택 후 결과의 선택 목록으로 확인한다.
- 빠른 연속 클릭으로 질문이 건너뛰거나 기록이 중복됨: 현재 화면의 선택 한 번만 적용되는지 확인한다.
- 작은 화면·키보드 사용 시 조작 불가: 긴 선택지 줄바꿈, 포커스 이동, 버튼 조작과 결과 안내를 확인한다.

## Task 1: 분기 데이터 확정과 검사

**Files:** `src/lib/mbti.ts`, `scripts/test-mbti.mjs`, `mbti-flowchart.md`.

**Interfaces:**
- `MbtiType`: 표에 있는 16개 MBTI 문자열의 union.
- `QuestionId`: 표에 있는 16개 질문 ID의 union.
- `QuizOption`: `label: string`과 `next`를 갖는다. `next`는 `{ kind: 'question'; id: QuestionId } | { kind: 'result'; type: MbtiType }`이다.
- `QuizQuestion`: `text: string`, `options: readonly QuizOption[]`.
- `START_QUESTION_ID: QuestionId`, `QUESTIONS: Record<QuestionId, QuizQuestion>`, `MBTI_TYPES: readonly MbtiType[]`를 export한다.

- [x] 표의 분기를 기준으로 assert 스크립트를 먼저 작성한다. 모든 참조 존재, 질문마다 2~3개 선택지, 빈 문구 없음, 순환 없음, 모든 질문 도달 가능, 모든 경로가 유효한 결과로 종료, 결과가 정확히 16개인지 검사한다. 대표 경로 `start → social → logic → emotion-logical → really → machines → ISTP`도 고정한다.
- [x] `node --experimental-strip-types scripts/test-mbti.mjs`로 데이터 모듈이 없어서 실패함을 확인한다. 테스트는 Node 내장 assert와 상대 경로 import만 사용한다.
- [x] 위 인터페이스와 표를 구현하고 같은 명령을 실행해 종료 코드 0 및 검사 성공을 확인한다.
- [x] 참고 Markdown의 빠진 감정 분기와 원본 문구를 정정하고, 병합한 질문은 앱에서 단순화한 것으로 설명한다.
