# 개발자 채용 포트폴리오 설계

## 목표와 대상

현재 프로젝트 허브에 개발자 채용용 포트폴리오를 `/portfolio` 경로로 추가한다. 주 독자는 채용 공고를 검토하는 인사 담당자이며, 기술 면접관도 대표 사례에서 문제 해결 과정과 담당 범위를 확인할 수 있어야 한다.

방문자가 첫 화면에서 다음 세 가지를 이해하는 것이 성공 기준이다.

- 양민준은 Java/Spring 기반 공공 정보시스템을 약 4년간 구축하고 운영한 개발자다.
- 이기종 데이터 연계, GIS·스마트시티, 운영 장애 해결이 반복해서 입증된 강점이다.
- 요구사항 분석부터 개발, 현장 설치, 장애 대응과 인수인계까지 서비스 전주기를 경험했다.

## 공개 원칙

사이트에는 채용 판단에 필요한 정보만 싣는다. 이름, 직무, 경력 기간, 회사와 담당 업무, 프로젝트, 기술, 학력, 자격, 공개 이메일, GitHub와 기술 블로그는 공개한다.

생년, 성별, 전화번호, 상세 거주지, 병역, 가족 연락처는 공개하지 않는다. 내부 IP, 계정, API 키, 서버 접속 정보, 주민·CCTV 원본 데이터도 포함하지 않는다. 화면 자료를 추가할 때에는 개인정보와 운영 환경 식별값을 먼저 마스킹한다.

원문에 `[확인 필요]`로 표시된 기여도, 절감률, 데이터 건수는 사용하지 않는다. “대폭 향상”, “무중단”, “오류 0건”처럼 측정 근거가 불명확한 표현은 정상화 여부와 구현 결과를 설명하는 문장으로 바꾼다.

## 정보 구조

### 1. 상단 소개

이름과 “백엔드 · 스마트시티/GIS 개발자”라는 직무를 가장 먼저 보여준다. 소개 문장은 “공공 정보시스템을 구축부터 운영까지 책임져 온 개발자”로 한다.

상단 행동 버튼은 세 개만 둔다.

- 대표 프로젝트로 이동
- 이력으로 이동
- 이메일 보내기

GitHub와 기술 블로그는 같은 영역의 보조 링크로 제공한다.

### 2. 이력 요약

인사 담당자가 빠르게 판단할 수 있도록 다음 사실을 짧은 카드와 문장으로 제시한다.

- 2022년 6월부터 이어진 약 4년의 개발 경력
- 전라남도와 11개 시·군 공공 정보시스템 경험
- 22개 시군 CCTV 통합플랫폼 운영
- REST API, MQTT, DB View, JSON/XML 기반 10종 이상 연계 경험

현재 회사 경력은 “대호이엔지 웹개발부서 · 주임 · 2022.06~현재”로 표시하고, 신규 구축·유지보수·서버 설치·사용자 교육을 담당했다는 설명을 붙인다.

### 3. 핵심 역량

핵심 역량은 세 범주로 제한한다.

1. 이기종 데이터 연계와 자동화
2. GIS·스마트시티 시스템 개발
3. 운영 장애 분석과 안정화

각 범주는 기술 이름을 나열하는 대신 한 가지 대표 행동과 근거 프로젝트를 연결한다.

### 4. 대표 사례

대표 사례는 세 개를 노출하고 모두 `문제 → 제약과 판단 → 구현 → 결과` 구조를 사용한다.

#### 전라남도 22개 시군 CCTV 동기화

- 문제: 실패 건별 로그 적재로 테이블과 DB I/O가 증가하고, 스키마 차이와 시군구 코드 변경으로 동기화가 중단되거나 데이터가 중복됐다.
- 판단: 개별 장애 패치보다 로그 구조와 데이터 검증, 스키마 복구 흐름을 함께 고쳐야 했다.
- 구현: JSON 통합 로그, 완료 상태 UPDATE, 필수값 검증, DB View 기반 위치 조회, 누락된 제약·테이블·컬럼 복구 로직을 적용했다.
- 결과: 22개 시군 동기화 운영을 정상화하고 장애 원인을 로그·DB·망연계 구간별로 확인할 수 있게 했다.

#### GeoSync — 영광군 KRAS 연계

- 문제: 기존 연계 프로그램이 SHP와 행정 데이터를 안정적으로 반영하지 못했다.
- 판단: 기존 코드를 반복 보수하는 대신 수집과 운영 반영 책임이 분리된 동기화 프로그램을 새로 구축했다.
- 구현: 수집·스테이징·운영 승격 단계, 급감 방지 가드, 17개 데이터셋 계약 검증, GeoTools 좌표 변환, 실행 이력과 반영 이어하기를 구현했다.
- 결과: KRAS 데이터와 SHP를 예약 수집하고 검증 후 운영 DB에 반영하는 흐름을 만들었다.

#### 남원 통합플랫폼

- 문제: 화재감지기, CCTV, ITS, 스마트횡단보도 등 서로 다른 규격과 통신 방식의 시설물을 하나의 플랫폼에 연계해야 했다.
- 판단: 명세와 실제 데이터가 다른 경우 임의 보정보다 로그 근거로 업체와 규격·좌표계·수집주기를 합의했다.
- 구현: REST API·MQTT·DB View 수집, 검증과 적재, 5개 시설물 관제 기능, 통계와 대시보드를 백엔드부터 화면까지 개발했다.
- 결과: 10종 이상 연계와 5개 시설물 관제 기능을 구축하고 검수를 완료했다.

실제 프로젝트 캡처는 현재 저장소에 제공되지 않았으므로 첫 구현 범위에서 제외한다. 첫 버전은 텍스트와 HTML/CSS 기반 처리 흐름 도식으로 완성하며, 마스킹한 이미지가 준비되면 `public/portfolio`에 WebP로 추가할 수 있다.

### 6. 기술, 학력과 자격

기술은 실제 업무 맥락에 따라 다음 범주로 표시한다.

- Backend: Java, Spring Boot, Spring Framework, Spring Batch, MyBatis

## 기술 설계

포트폴리오는 데이터 조회나 인증이 필요 없는 정적 서버 컴포넌트로 만든다. 기존 Next.js App Router와 Tailwind CSS 4만 사용하며 의존성을 추가하지 않는다.

- `src/app/portfolio/page.tsx`: 메타데이터와 전체 페이지 조립
- `src/app/portfolio/portfolio-data.ts`: 공개 검토를 마친 포트폴리오 문구와 배열 데이터
- `src/components/portfolio/PortfolioHero.tsx`: 소개와 행동 링크
- `src/components/portfolio/ExperienceSummary.tsx`: 이력 요약과 핵심 역량
- `src/components/portfolio/CaseStudy.tsx`: 세 대표 사례의 공통 표현
- `src/components/portfolio/CareerTimeline.tsx`: 연도별 경력
- `src/components/portfolio/Credentials.tsx`: 기술·학력·자격
- `src/components/portfolio/PortfolioFooter.tsx`: 연락처와 외부 링크
- `src/app/page.tsx`: 기존 프로젝트 목록에 포트폴리오 카드 추가

컴포넌트는 모두 서버 컴포넌트로 유지한다. 섹션 이동은 브라우저 앵커를 사용하고, 애니메이션과 필터 상태를 위한 클라이언트 코드는 추가하지 않는다. 색상은 기존 사이트의 파란색 계열을 유지하되 흰색 배경, 짙은 본문, 청록색 성과 강조를 사용해 이력서처럼 읽히게 한다.

## 반응형과 접근성

- 모바일에서는 모든 영역을 한 열로 쌓고 데스크톱에서는 이력 요약과 기술 목록만 다열로 배치한다.
- 문서 구조는 `header`, `nav`, `main`, `section`, `footer`와 순차적인 제목 수준을 사용한다.
- 링크와 버튼에는 키보드 포커스 스타일을 제공한다.
- 색상만으로 역량이나 상태를 구분하지 않는다.
- 장식 도형은 스크린리더에서 제외한다.
- 사용자가 모션 감소를 설정한 경우 이동 효과를 적용하지 않는다.

## 오류와 빈 상태

정적 데이터만 사용하므로 네트워크 오류 상태는 없다. 선택적 이미지가 없는 경우에도 사례 카드가 완성된 레이아웃을 유지한다. 외부 링크는 새 탭으로 열며 `noopener noreferrer`를 사용한다.

## 검증

별도 테스트 프레임워크를 추가하지 않는다. 이 변경의 핵심 위험은 콘텐츠 누락과 공개 정보 오류이므로 다음 검증을 수행한다.

- `npm run lint`: TypeScript와 JSX 규칙 확인
- `npm run build`: 정적 렌더링과 메타데이터 빌드 확인
- 모바일·데스크톱에서 Hero, 앵커 이동, 타임라인, 외부 링크를 수동 확인
- 페이지 소스와 화면에서 전화번호, 생년, 상세 주소, 가족 연락처, 내부 접속 정보가 없는지 검색
- 원문에만 있는 검증 전 수치와 `[확인 필요]` 문구가 노출되지 않는지 검색
