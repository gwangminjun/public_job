# 알고리즘 단권화

원문 9개를 7개 주제로 통합했다. `전공 - 알고리즘.md`와 개별 문서의 중복 본문은 한 번만 정리했다. 각 주제의 자세한 예제는 화면의 **원문 참고**에서 확인한다.

## 탐색과 이진 탐색 트리

**탐색(Search) = 여러 원소로 구성된 데이터에서 원하는 값을 가진 원소를 찾는 것.** 자료구조별 대표 탐색: 리스트 → 순차·이진 탐색 / 트리 → BST·2-3-4·레드-블랙·B-트리 / 해시 테이블.

**암기 흐름: 순차 → 정렬된 배열의 이진 탐색 → BST → 균형 유지.**

| 방법 | 전제와 동작 | 탐색 시간 |
|---|---|---|
| 순차 탐색 | 정렬 불필요, 처음부터 하나씩 비교 | O(n) |
| 이진 탐색 | 정렬된 배열, 가운데와 비교해 범위를 절반으로 축소 | O(log n) |
| BST | 왼쪽 서브트리 < 현재 키 < 오른쪽 서브트리 | O(h), 균형 시 O(log n), 편향 시 O(n) |
| 2-3-4 트리 | 모든 리프의 깊이가 같고 노드에 여러 키 저장 | O(log n) |

### 순차 탐색(Sequential Search)

- 데이터를 하나씩 순서대로 비교. 구현이 간단하고 **정렬되지 않은 작은 데이터**에 적합.
- 복잡도: 탐색 O(n), 삭제 O(n). 삽입은 맨 앞·뒤 단순 삽입이면 O(1), 위치를 탐색한 뒤 삽입하면 O(n).

### 이진 탐색(Binary Search)

과정: ① 정가운데 원소와 탐색 키 비교 → ② 같으면 종료 → ③ 키가 작으면 왼쪽 절반, 크면 오른쪽 절반만 탐색 → ④ 남은 구간에서 반복.

- 반복마다 대상이 약 절반으로 감소하는 **분할 정복(Divide and Conquer)** 방식.
- 정렬되지 않은 배열은 먼저 정렬해야 하며, **삽입·삭제가 빈번한 경우 부적합**하다.
- 연결 리스트는 가운데 원소에 즉시 접근할 수 없어(가운데까지 순서대로 이동) O(log n) 효율을 낼 수 없다. 배열은 인덱스로 바로 접근 가능.

### 이진 탐색 트리(BST)

- 조건: `왼쪽 자식 < 부모 < 오른쪽 자식`. 루트에서 값의 크기 관계에 따라 왼쪽/오른쪽으로 내려가며 탐색.
- 탐색 시간은 **키 비교 횟수 = 트리의 높이 h**에 비례 → O(h). 균형이면 h ≈ log n, 경사 트리면 h ≈ n.
- 삽입·삭제 시 기존 노드의 이동이 거의 없다(비교하며 위치를 찾아 연결).
- **삭제 3가지 경우**: 자식 0개 → 그냥 제거 / 자식 1개 → 자식 서브트리를 부모에 연결 / 자식 2개 → **후속자(Successor, 오른쪽 서브트리의 최솟값)** 또는 **선행자(Predecessor, 왼쪽 서브트리의 최댓값)** 값으로 교체한 뒤 그 노드를 삭제.
- **경사 트리(Skewed Tree)**: 1, 2, 3, 4, 5 순 삽입처럼 한쪽으로 치우친 트리. 탐색이 O(n)까지 나빠진다. 해결책이 **균형 탐색 트리**(2-3-4, 레드-블랙, AVL, B-트리).

### 2-3-4 트리

노드 이름의 숫자는 **최대 자식 수** 기준이다.

| 노드 종류 | 키 개수 | 최대 자식 수 |
|---|---|---|
| 2-노드 | 1 | 2 |
| 3-노드 | 2 | 3 |
| 4-노드 | 3 | 4 |

- **모든 리프 노드의 레벨이 동일** → 삽입/삭제에도 경사 트리가 되지 않고 높이가 O(log n)으로 유지.
- **4-노드 분할**: 삽입 중 4-노드 `[10|20|30]`을 만나면 가운데 키 20을 부모로 올리고 [10], [30]으로 분할한다. 이 방식으로 균형을 유지한다.
- 단점: 한 노드가 여러 키·자식을 관리해 **노드 구조와 구현이 복잡**하고, 그대로 구현하면 관리 비용 때문에 BST보다 느려질 수도 있다.

> 주의: 일반 BST가 항상 O(log n)은 아니다. 삽입 순서에 따라 편향될 수 있다. 배열 중간 삽입·삭제에는 원소 이동 비용도 든다.

## 균형 탐색 트리와 해싱

| 구조 | 기억할 조건 | 용도·성능 |
|---|---|---|
| 레드-블랙 트리 | 색상 규칙 + 회전으로 균형 유지하는 BST | 탐색·삽입·삭제 O(log n) |
| B-트리 | 한 노드에 여러 키·자식, 모든 리프 깊이 동일 | 디스크 접근을 줄이는 다방향 균형 트리, DB 인덱스·파일 시스템 |
| 해시 테이블 | 키를 해시 함수로 주소에 직접 대응 | 평균 O(1), 최악 O(n) |

### 레드-블랙 트리의 5가지 조건

1. 모든 노드는 빨강 또는 검정이다.
2. **루트 노드는 검정**이다.
3. 모든 NIL 리프 노드는 검정이다.
4. **빨강 노드의 자식은 반드시 검정**이다(빨강이 연속으로 나올 수 없음).
5. 임의의 노드에서 그 아래 모든 리프까지 가는 경로의 **검정 노드 수가 동일**하다.

- 새 노드는 **빨강으로 삽입**한다. 규칙이 깨지면 **색상 변경(Recoloring)과 좌/우 회전(Rotation)**으로 복구한다.
- 부모와 삼촌이 모두 빨강 → 부모·삼촌을 검정, 조부모를 빨강으로 재색칠.
- 삼촌이 검정 → 노드 위치에 따라 LL·LR·RL·RR 형태를 판단해 회전 + 색상 변경.
- 균형 특성: 가장 긴 루트→리프 경로가 가장 짧은 경로의 **2배를 넘지 않는다.**

### B-트리

- 노드 내부의 키는 **오름차순 정렬**되고, 키가 k개면 자식은 **k+1개**다.
- 최소 차수(Minimum Degree) t 기준: 한 노드 최대 키 `2t−1`개, 최대 자식 `2t`개. 비어 있지 않은 루트는 최소 1개의 키를 가진다.
- 삽입 시 노드가 가득 차면 **가운데 키를 부모로 올리고 노드를 분할**해 모든 리프 레벨을 동일하게 유지한다.

### 해싱(Hashing)

**키(Key)를 해시 함수에 넣어 저장 위치(해시 주소)를 직접 계산**하는 방법. 해시 테이블의 각 저장 위치를 **슬롯(Slot)**이라 한다. 예: 테이블 크기 10에서 `h(27) = 27 mod 10 = 7` → 7번 슬롯에 저장. 탐색·삽입·삭제 평균 O(1).

**해시 함수 종류**

- **제산 잔여법**: `h(k) = k mod m` (m은 테이블 크기).
- **비닝(Binning)**: 키 공간을 테이블 크기에 맞춰 구간으로 나누고 각 구간을 슬롯에 대응 (0~99 → 슬롯 0, 100~199 → 슬롯 1 …).
- **중간 제곱법**: 키를 제곱한 뒤 중간 부분의 숫자·비트를 추출 (123² = 15129 → 512).
- **문자열 해싱**: 앞부분 일부 사용(비슷한 접두어가 많으면 충돌 증가) 또는 문자 코드값의 합에 제산법 적용 (A+B+C = 65+66+67 = 198 → 198 mod 크기).

**충돌(Collision)**: 서로 다른 키가 같은 해시 주소로 계산되는 현상. 적재율은 `저장된 항목 수 / 테이블 크기`.

```text
충돌 해결
├─ 개방 해싱(Open Hashing) → 체이닝(Chaining)
└─ 폐쇄 해싱(Closed Hashing) → 개방 주소법(Open Addressing)
     ├─ 선형 탐사  ├─ 이차 탐사  └─ 이중 해싱
```

- **개방 해싱(체이닝)**: 각 슬롯을 연결 리스트의 헤더처럼 사용해 충돌 데이터를 연결 구조로 저장 (12, 22, 32가 모두 2번 슬롯 → `2 → [12] → [22] → [32]`).
- **폐쇄 해싱(개방 주소법)**: 테이블 안의 다른 빈 슬롯을 찾는다. 여러 슬롯을 버킷으로 묶고 가득 차면 오버플로 영역을 쓰는 변형도 있다.
- **선형 탐사**: `h(k)+1, h(k)+2, …` 순서로 다음 슬롯을 확인. 연속 영역에 데이터가 몰리는 **1차 군집화(Primary Clustering)** 발생.
- **이차 탐사**: `h(k)+1², h(k)+2², h(k)+3², …` 간격으로 탐색 (기본 위치 5 → 6, 9, 14). 1차 군집화를 완화하지만 같은 시작 주소는 같은 탐사 경로를 따른다.

> 주의: **개방 해싱**과 **개방 주소법**을 혼동하지 말 것(개방 주소법은 폐쇄 해싱이다). 해싱의 O(1)은 최악 보장이 아니다. B-트리의 차수 정의는 교재 규약을 확인한다.

## 욕심쟁이 방법

**현재 상황에서 가장 좋아 보이는 선택을 반복한다.** 단, **국부 최적해(Local Optimum)가 항상 전체 최적해(Global Optimum)를 보장하지는 않으므로**, 그리디로 최적해를 구할 수 있는 문제에만 적용해야 한다.

| 문제·알고리즘 | 선택 기준·조건 |
|---|---|
| 거스름돈 | 큰 액수의 동전부터 선택, 임의의 동전 체계에서는 최적 보장 불가 |
| 분할 가능 배낭 | **단위 무게당 이익(이익/무게)**이 큰 물체부터, 남은 용량만큼 쪼개 담기 |
| Kruskal | 작은 간선부터 선택하되 사이클 방지, 최소 신장 트리 |
| Prim | 현재 트리와 외부 정점을 잇는 최소 간선, 최소 신장 트리 |
| Dijkstra | 현재 최단거리 후보가 가장 작은 정점 확정, 음수 간선 없는 경우 |

- **거스름돈 반례**: 동전 `{1, 3, 4}`, 금액 6 → 그리디는 `4+1+1`(3개), 최적은 `3+3`(2개).
- **분할 가능 배낭**: 배낭 용량을 초과하지 않으면서 이익의 합을 최대화. 물체를 쪼갤 수 있으므로 이익/무게가 큰 순으로 넣고 마지막 물체는 남은 용량만큼만 넣는다.

> 주의: 분할 가능 배낭의 이익/무게 전략을 0/1 배낭(쪼갤 수 없는 경우)에 그대로 적용하면 최적해를 보장하지 못한다.

## 비교 기반 정렬

### 정렬의 분류 (용어)

- **내부 정렬**: 데이터를 전부 주기억장치(RAM)에 올려 정렬. **외부 정렬**: 메모리에 다 담기지 않아 보조기억장치(디스크) 활용.
- **비교 기반 정렬**: 두 키 값을 직접 비교해 순서 결정(선택·버블·삽입·셸·퀵·합병·힙). 성능 판단 기준은 **키 비교 횟수**.
- **분포 기반 정렬**: 값의 범위·출현 횟수·자릿수를 이용(계수·기수·버킷). 조건이 맞으면 O(n)도 가능.
- **안정적 정렬**: 같은 키의 기존 상대 순서 유지. 예: `3-A, 1, 3-B, 2` → `1, 2, 3-A, 3-B`면 안정.
- **제자리 정렬**: 입력 크기에 비례하는 추가 공간을 쓰지 않고 기존 공간을 주로 활용.

| 정렬 | 핵심 동작 | 최선 / 평균 / 최악 | 안정 | 제자리 |
|---|---|---|---|---|
| 선택 | 미정렬 부분의 최솟값을 찾아 맨 앞과 교환 | n² / n² / n² | X | O |
| 버블 | 인접 원소를 차례로 비교·교환, 한 번 돌면 최댓값이 끝에 확정 | n / n² / n² | O | O |
| 삽입 | 하나를 뽑아 앞의 정렬된 구간의 제자리에 삽입 | n / n² / n² | O | O |
| 셸 | gap 간격의 부분 배열마다 삽입 정렬, gap을 줄여 반복 | gap 수열에 의존 | X | O |
| 퀵 | 피벗 기준으로 작은 값/큰 값 분할 후 재귀 | n log n / n log n / n² | X | 통상 O |
| 합병 | 절반씩 분할한 뒤 정렬하면서 병합 | n log n / n log n / n log n | O | X |

위 표의 시간은 Big-O 기준. 버블 최선 O(n)은 **교환이 없으면 조기 종료하는 구현**에서 성립한다.

### 정렬별 핵심 포인트

- **선택**: 입력 초기 순서에 크게 민감하지 않음. 한 줄 암기 — "최솟값을 찾아 앞으로 보낸다."
- **버블**: 교환이 많이 발생. 반복할수록 이미 정렬된 끝부분을 제외할 수 있다.
- **삽입**: `[정렬된 부분 | 미정렬 부분]`으로 보고 하나씩 삽입. 초기 순서에 민감하며 **거의 정렬된 데이터에 효율적**.
- **셸**: 삽입 정렬은 먼 위치로 한 칸씩만 이동하는 단점이 있다. 셸은 gap = 4 → 2 → 1처럼 간격을 줄이며 부분 배열에 삽입 정렬을 적용, 한 번에 먼 거리 이동이 가능하다. gap이 h면 h개의 부분 배열이 생기고, 마지막 gap=1은 일반 삽입 정렬과 같다. **gap 수열에 따라 성능이 달라진다.**
- **퀵**: **피벗(Pivot)** = 분할 기준 데이터. 보통 첫/마지막/가운데 원소 중 선택. 양방향 분할에서 left는 왼쪽부터 피벗보다 **큰** 값을, right는 오른쪽부터 피벗보다 **작은** 값을 찾아 서로 교환하고, 분할이 끝나면 **피벗은 최종 자기 자리를 잡는다.** 피벗이 계속 최소/최댓값이면 한쪽으로 치우쳐 최악 O(n²).
- **합병**: ① 배열을 거의 같은 크기 둘로 분할 → ② 각 부분에 재귀 적용 → ③ 정렬된 두 배열의 앞쪽 원소를 비교하며 하나로 병합. 입력 순서에 따른 성능 변화가 적고 병합용 추가 배열 O(n)이 필요하다.

### 분할 정복 관점 비교

| 구분 | 분할 | 정복 | 결합 |
|---|---|---|---|
| 퀵 정렬 | O (피벗 기준, **분할할 때 일함**) | O | **X (결합 과정 없음)** |
| 합병 정렬 | O (절반씩) | O | **O (합칠 때 정렬함)** |

> 주의: 셸 정렬의 복잡도를 간격 수열과 무관하게 하나로 외우지 않는다. 합병 정렬은 같은 키에서 왼쪽 원소를 먼저 선택해야 안정성이 유지된다. 퀵의 재귀 스택 비용은 별도다.

## 힙과 힙 정렬

**힙 = 완전 이진 트리 + 부모·자식 간 순서 조건.** 완전 이진 트리는 위에서부터, 왼쪽부터 빈자리 없이 채워지는 이진 트리다.

| 구분 | 조건 | 루트 |
|---|---|---|
| 최대 힙 | 부모 ≥ 자식 | 최댓값 |
| 최소 힙 | 부모 ≤ 자식 | 최솟값 |

- **배열 구현**: 완전 이진 트리라 빈 공간 없이 1차원 배열로 저장 가능. 0부터 시작하면 부모 `floor((i−1)/2)`, 왼쪽 자식 `2i+1`, 오른쪽 자식 `2i+2`.
- **삽입**: 배열 마지막에 넣고 부모와 비교하며 조건을 만족할 때까지 위로 이동 → O(log n).
- **삭제(루트)**: ① 루트 제거 → ② 마지막 데이터를 루트로 이동 → ③ 마지막 위치 삭제 → ④ 자식과 비교하며 아래로 이동해 힙 재구성 → O(log n).

### 힙 정렬

**오름차순 → 최대 힙, 내림차순 → 최소 힙.**

과정: ① 배열을 힙으로 변환 → ② 루트(최댓값)를 정렬될 위치(마지막)로 교환 → ③ 힙 크기 1 감소 후 루트에서 내려가며 힙 복구(heapify) → ④ 반복.

**초기 힙 구축 두 방법**

| 방법 | 방식 | 전체 구축 시간 |
|---|---|---|
| 순차 삽입 | 원소를 하나씩 넣으며 위로 올림 | O(n log n) |
| 일괄 구축 | 배열 전체를 트리로 보고 가장 아래쪽 부모부터 heapify | **O(n)** |

- 전체 정렬 시간: 바깥 반복 ≈ n번 × heapify ≈ log n → **최선·평균·최악 모두 O(n log n)**.
- **비안정적·제자리 정렬**이며 입력 초기 순서에 따른 성능 변화가 크지 않다.

> 주의: 힙은 BST가 아니다. 형제끼리나 서브트리 전체의 대소 관계를 보장하지 않는다. "하나씩 삽입" 구축은 O(n log n), "일괄(bottom-up)" 구축은 O(n)으로 구분해 외운다.

## 분포 기반 정렬

**비교만 사용하는 정렬의 최악 시간 하한은 Ω(n log n)이다.** (O = 상한, Ω = 하한.) 계수·기수·버킷 정렬은 비교만 쓰는 것이 아니므로 이 하한에 직접 묶이지 않고, 조건이 맞으면 O(n) 수준도 가능하다.

| 정렬 | 방법 | 시간·조건 |
|---|---|---|
| 계수 | 값별 출현 횟수 → 누적 횟수 → 결과 배열에 배치 | O(n+k), k는 키 범위 크기 |
| 기수 | 자릿수마다 안정 정렬 반복 | O(d(n+b)), d는 자릿수·b는 진법/버킷 수 |
| 버킷 | 값 범위를 버킷으로 나눠 각각 정렬 후 연결 | 균등 분포에서 평균 O(n), 편중 시 악화 |

### 계수 정렬(Counting Sort)

예: 입력 `2 5 3 2 3 1` → 출현 횟수 `1:1, 2:2, 3:2, 4:0, 5:1` → 누적 횟수 `1, 3, 5, 5, 6` → 누적 값을 위치로 사용해 배치.

- 사용하기 좋은 경우: 값 범위 k가 작을 때, k가 n에 비례할 때, 범위를 미리 알 때.
- **안정적, 제자리 아님.** 범위가 너무 크면 메모리 낭비가 커서 범용적으로 쓰기 어렵다.

### 기수 정렬(Radix Sort)

- **LSD**(Least Significant Digit): 낮은 자리부터 — 일 → 십 → 백. **MSD**(Most Significant Digit): 높은 자리부터 — 백 → 십 → 일, 같은 접두 값 그룹을 재귀 정렬.
- **각 자릿수 정렬에 안정 정렬(보통 계수 정렬)을 사용해야 이전 자릿수 결과가 유지된다.**
- 자릿수 수와 각 자리 값의 범위에 따라 성능이 달라진다.

### 버킷 정렬(Bucket Sort)

과정: ① 버킷 여러 개 생성 → ② 데이터를 해당 버킷에 분배 → ③ 각 버킷 내부 정렬(보통 삽입 정렬) → ④ 버킷 순서대로 연결.

- 좋은 조건: 데이터가 값 범위에 **확률적으로 균등 분포** + 버킷 수가 데이터 수에 적절히 비례 → 평균 O(n).
- 한 버킷에 몰리고 내부에서 삽입 정렬을 쓰면 최악 O(n²)까지 가능. 안정성은 내부 정렬 구현에 따라 다르다.

### 전체 정렬 비교표

| 알고리즘 | 기반 | 안정 | 제자리 | 시간 핵심 |
|---|---|---|---|---|
| 선택 | 비교 | X | O | O(n²) |
| 버블 | 비교 | O | O | O(n²) |
| 삽입 | 비교 | O | O | 최악 O(n²) |
| 셸 | 비교 | X | O | gap에 따라 다름 |
| 퀵 | 비교 | X | 통상 O | 평균 O(n log n), 최악 O(n²) |
| 합병 | 비교 | O | X | O(n log n) |
| 힙 | 비교 | X | O | 최선·평균·최악 O(n log n) |
| 계수 | 분포 | O | X | O(n+k) |
| 기수 | 분포 | 조건부 O | 통상 X | 자릿수에 비례 |
| 버킷 | 분포 | 구현에 따름 | X | 평균 O(n) 가능 |

> 주의: 분포 정렬이 무조건 O(n)은 아니다. 계수의 k, 기수의 d·b, 버킷의 분포 조건을 함께 적는다.

## 그래프와 순회

**G = (V, E)**: V는 정점(Vertex)의 집합, E는 간선(Edge)의 집합.

- **무방향 그래프**: 간선에 방향 없음, 양쪽으로 이동 가능. **방향 그래프**: `A → B`와 `B → A`는 다른 간선.
- **가중 그래프**: 간선에 거리·비용·시간 등의 **가중치(Weight)** 저장.
- **트리 = 연결된 무방향 그래프 + 사이클 없음.** 정점이 n개인 트리의 간선 수는 항상 **n−1**.

### 그래프의 구현

| 구분 | 방식 | 특징 |
|---|---|---|
| 인접 행렬 | 2차원 배열, 간선 있으면 1(자기 자신 대각선은 0) | 공간 O(V²), 간선 유무 확인 O(1) |
| 인접 리스트 | 각 정점의 인접 정점을 리스트로 연결 | 공간 O(V+E), **희소 그래프**에 메모리 효율적 |

- 가중 그래프의 인접 행렬은 가중치를 저장하고, 최단 경로 문제에서는 연결되지 않은 정점 사이를 보통 `∞`로 표현한다(일반 인접 행렬의 "간선 없음 = 0"과 구분).
- 인접 리스트에서 가중치는 `A → (B, 5) → (C, 3)`처럼 정점과 함께 저장한다.

### 그래프 순회 — DFS와 BFS

순회 = 모든 정점을 체계적으로 방문하는 것. 정점은 **방문 정점**(방문 완료) / **주변 정점**(인접하지만 미방문) / **미도달 정점**(아직 접근 못 함)으로 구분한다.

**DFS(깊이 우선 탐색)** — 한 방향으로 가능한 깊게, 막히면 되돌아온다. **스택** 또는 재귀로 구현.

1. 시작 정점을 방문하고 스택에 push.
2. 스택 top 정점에서 방문하지 않은 인접 정점을 찾는다.
3. 있으면 방문하고 push, 없으면 pop하여 이전 정점으로 복귀.
4. 스택이 빌 때까지 반복.

방문한 정점과 방문에 사용된 간선으로 구성된 트리를 **깊이 우선 탐색 트리(DFS Tree)**라 한다.

**BFS(너비 우선 탐색)** — 시작 정점에서 가까운 정점부터 층별로. **큐** 사용.

1. 시작 정점을 방문하고 큐에 삽입.
2. 큐에서 정점 하나를 꺼낸다.
3. 그 정점의 방문하지 않은 인접 정점을 모두 방문하고 큐에 삽입.
4. 큐가 빌 때까지 반복.

| 구분 | DFS | BFS |
|---|---|---|
| 자료구조 | 스택 | 큐 |
| 탐색 방법 | 한 방향으로 깊게 | 가까운 정점부터 층별 |
| 특징 | 막히면 이전 정점으로 복귀 | 같은 깊이의 정점을 먼저 모두 방문 |

- 인접 리스트 기준 DFS·BFS는 **O(V+E)**, 인접 행렬 기준은 통상 **O(V²)**. 방문 표시로 반복 방문을 막는다.
- BFS는 **무가중 그래프**에서 시작점 기준 간선 수가 최소인 경로를 구할 수 있다.

### 위상 정렬 · 연결 성분

- **위상 정렬(Topological Sort)**: **DAG(방향 비순환 그래프)**의 정점들을 모든 간선의 방향 관계를 만족하도록 한 줄로 나열. 방향 그래프이면서 사이클이 없어야만 가능하다.
- DFS 이용법: 한 정점의 탐색이 완전히 끝나는 시점에 스택에 저장 → 모든 DFS 종료 후 **스택에서 꺼내는 순서(= DFS 종료 순서의 역순)**가 위상 정렬 결과. 그래프 구조에 따라 **답이 여러 개**일 수 있다 (`A→B→D, A→C→D`에서 `A B C D`와 `A C B D` 모두 가능).
- **연결 성분(Connected Component)**: **무방향** 그래프에서 모든 정점 사이에 경로가 존재하는 최대 부분 그래프. `A—B—C`와 `D—E`가 있으면 연결 성분은 `{A,B,C}`, `{D,E}` 2개. DFS/BFS로 구한다.
- **강연결 성분(SCC, Strongly Connected Component)**: **방향** 그래프에서 임의의 두 정점 A, B에 대해 `A→…→B`와 `B→…→A` 경로가 **모두** 존재하는 최대 부분 그래프.

> 주의: 사이클이 있는 방향 그래프에는 위상 정렬이 없다. BFS의 최단경로 성질을 임의의 가중 그래프에 적용하지 않는다. 연결 성분은 무방향, 강연결 성분은 방향 그래프 개념이다.
