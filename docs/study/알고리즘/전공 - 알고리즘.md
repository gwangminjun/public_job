# 알고리즘 정리

## 1. 탐색 알고리즘

탐색(Search)은 여러 개의 원소로 구성된 데이터에서 **원하는 값을 가진 원소를 찾는 것**이다.

자료구조에 따라 대표적인 탐색 방법은 다음과 같다.

- **리스트 형태**
  - 순차 탐색
  - 이진 탐색
- **트리 형태**
  - 이진 탐색 트리
  - 2-3-4 트리
  - 레드-블랙 트리
  - B-트리
- **해시 테이블**
  - 해시 함수
  - 충돌 해결 방법

---

### 1.1 순차 탐색(Sequential Search)

데이터를 처음부터 하나씩 차례대로 비교하면서 원하는 값을 찾는 방법이다.

#### 특징

- 데이터를 **하나씩 순서대로 비교**한다.
- 데이터가 정렬되어 있을 필요가 없다.
- 구현이 간단하다.
- **정렬되지 않고 크기가 작은 데이터**에 적합하다.

#### 시간 복잡도

| 연산 | 시간 복잡도 |
|---|---:|
| 탐색 | **O(n)** |
| 삭제 | **O(n)** |
| 삽입 | 일반적으로 **O(1)** 또는 **O(n)** |

삽입은 위치에 따라 달라진다.

- 맨 앞이나 맨 뒤에 단순 삽입하는 경우: `O(1)`이 가능
- 특정 위치를 탐색한 뒤 삽입하는 경우: `O(n)`

---

### 1.2 이진 탐색(Binary Search)

**정렬된 리스트**에서 가운데 원소와 탐색 키를 비교하고, 탐색 범위를 절반씩 줄여가면서 원하는 값을 찾는 방법이다.

#### 탐색 과정

1. 정가운데 원소와 탐색 키를 비교한다.
2. 두 값이 같으면 탐색을 종료한다.
3. 탐색 키가 더 작으면 왼쪽 절반만 탐색한다.
4. 탐색 키가 더 크면 오른쪽 절반만 탐색한다.
5. 남은 구간에서 다시 가운데 원소를 비교한다.

예:

```text
1  3  5  7  9  11  13
         ↑
       가운데
```

`11`을 찾는 경우 `7`과 비교한 뒤 오른쪽 절반만 탐색한다.

#### 특징

- 데이터가 **반드시 정렬되어 있어야 한다.**
- 탐색을 반복할 때마다 대상 원소의 개수가 약 절반으로 감소한다.
- **분할 정복(Divide and Conquer)** 방식이 적용된다.
- 정렬되어 있지 않은 배열은 먼저 정렬해야 한다.
- 삽입과 삭제가 빈번한 경우에는 부적합하다.

#### 시간 복잡도

```text
O(log n)
```

#### 연결 리스트에서의 이진 탐색

연결 리스트에서는 가운데 원소에 즉시 접근할 수 없기 때문에 이진 탐색의 장점을 제대로 사용할 수 없다.

배열은 인덱스를 이용해 가운데 값에 바로 접근할 수 있지만, 연결 리스트는 가운데 노드까지 순서대로 이동해야 한다.

따라서 연결 리스트에서는 효율적인 `O(log n)` 이진 탐색이 어렵다.

---

### 1.3 이진 탐색 트리(Binary Search Tree, BST)

루트 노드에서 시작하여 **값의 크기 관계에 따라 왼쪽 또는 오른쪽 경로로 내려가며 탐색**하는 트리이다.

기본 조건:

```text
왼쪽 자식 < 부모 < 오른쪽 자식
```

예:

```text
        8
      /   \
     4     12
    / \   / \
   2   6 10  14
```

`10`을 탐색한다면 다음과 같이 진행한다.

```text
8 → 12 → 10
```

#### 시간 복잡도

이진 탐색 트리의 탐색 시간은 **키 값을 비교하는 횟수**, 즉 트리의 높이에 비례한다.

트리의 높이를 `h`라고 하면:

```text
O(h)
```

균형 잡힌 트리라면:

```text
h ≈ log n
→ O(log n)
```

경사 트리가 되면:

```text
h ≈ n
→ O(n)
```

#### 삽입과 삭제

- 기존 노드의 이동이 거의 발생하지 않는다.
- 값의 크기를 비교하면서 적절한 위치를 찾아 연결한다.

#### 삭제 연산

삭제할 노드의 자식 개수에 따라 세 가지 경우로 나눈다.

##### 1) 자식 노드가 없는 경우

해당 노드를 그냥 삭제한다.

```text
    5
   / \
  3   7
```

`3`을 삭제하면:

```text
    5
     \
      7
```

##### 2) 자식 노드가 하나인 경우

삭제할 노드를 제거하고 **자식 서브트리를 부모와 연결**한다.

```text
    5
     \
      7
       \
        9
```

`7`을 삭제하면:

```text
    5
     \
      9
```

##### 3) 자식 노드가 두 개인 경우

**후속자(Successor)** 또는 **선행자(Predecessor)**를 이용한다.

일반적으로 후속자를 사용한다면 오른쪽 서브트리에서 가장 작은 값을 찾는다.

```text
       8
      / \
     4   12
        /  \
       10  14
```

`8`을 삭제하면 후속자 `10`이 그 자리를 대신할 수 있다.

```text
       10
      /  \
     4    12
            \
             14
```

정확히는 삭제할 노드의 값을 후속자 값으로 교체한 뒤 기존 후속자 노드를 삭제한다.

#### 문제점: 경사 트리

원소의 삽입 순서에 따라 한쪽으로 치우친 **경사 트리(Skewed Tree)**가 될 수 있다.

예를 들어 `1, 2, 3, 4, 5` 순서로 삽입하면:

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

이 경우 탐색 시간이 `O(n)`까지 나빠질 수 있다.

이를 해결하기 위해 **균형 탐색 트리**를 사용한다.

대표적인 균형 탐색 트리:

- 2-3-4 트리
- 레드-블랙 트리
- AVL 트리
- B-트리

---

### 1.4 2-3-4 트리

2-3-4 트리는 하나의 노드가 여러 개의 키와 자식을 가질 수 있는 **균형 탐색 트리**이다.

노드 이름의 숫자는 **최대 자식 수**를 기준으로 한다.

| 노드 종류 | 키 개수 | 자식 수 |
|---|---:|---:|
| 2-노드 | 1 | 최대 2 |
| 3-노드 | 2 | 최대 3 |
| 4-노드 | 3 | 최대 4 |

예를 들어 3-노드는 다음과 같이 구성될 수 있다.

```text
      [10 | 20]
      /   |   \
    <10 10~20 >20
```

#### 특징

- **모든 리프 노드의 레벨이 동일**하다.
- 항상 균형을 유지하는 균형 탐색 트리이다.
- 삽입/삭제가 발생해도 경사 트리가 되지 않는다.
- 트리의 높이가 `O(log n)` 수준으로 유지된다.

#### 4-노드 분할

삽입 과정에서 4-노드를 만나면 **노드 분할을 우선 수행**한다.

예:

```text
[10 | 20 | 30]
```

가운데 값 `20`을 부모로 올리고 양쪽으로 분할한다.

```text
       [20]
      /    \
   [10]    [30]
```

이러한 방식으로 트리의 균형을 유지한다.

#### 시간 복잡도

균형이 유지되므로 탐색·삽입·삭제는 일반적으로 다음과 같다.

```text
O(log n)
```

#### 장점

- 삽입과 삭제 후에도 균형을 유지한다.
- 경사 트리가 되지 않는다.
- 탐색 성능이 안정적이다.

#### 단점

하나의 노드에 여러 개의 키와 여러 자식을 관리해야 하므로 일반적인 이진 탐색 트리보다 **노드 구조와 구현이 복잡하다.**

따라서 그대로 구현하면 관리 비용 때문에 이진 탐색 트리보다 느려질 가능성도 있다.

---

### 1.5 핵심 비교

| 탐색 방법 | 조건 | 평균/일반 탐색 시간 | 특징 |
|---|---|---:|---|
| 순차 탐색 | 정렬 불필요 | `O(n)` | 처음부터 하나씩 탐색 |
| 이진 탐색 | 정렬 필요 | `O(log n)` | 범위를 절반씩 감소 |
| 이진 탐색 트리 | BST 조건 | `O(log n)` | 경사 트리가 되면 `O(n)` |
| 2-3-4 트리 | 균형 유지 | `O(log n)` | 모든 리프 레벨 동일 |

#### 시험용 핵심

```text
순차 탐색
→ 처음부터 하나씩 탐색
→ O(n)

이진 탐색
→ 정렬된 배열
→ 가운데 값을 기준으로 범위를 절반씩 감소
→ O(log n)

이진 탐색 트리
→ 왼쪽 < 부모 < 오른쪽
→ 균형 상태 O(log n)
→ 경사 트리가 되면 O(n)

2-3-4 트리
→ 2/3/4개의 자식을 가질 수 있음
→ 모든 리프 노드의 레벨 동일
→ 4-노드는 분할
→ 항상 균형 유지
→ O(log n)
```

# 2. 욕심쟁이 방법(Greedy)

현재 상황에서 가장 좋아 보이는 선택을 반복하는 방법이다.

하지만

> 국부적인 최적해(Local Optimum)가 항상 전체 최적해(Global Optimum)를 보장하는 것은 아니다.

따라서 그리디 방법으로 최적해를 구할 수 있는 문제에만 적용해야 한다.

대표적인 알고리즘:

- 크루스칼(Kruskal)
- 프림(Prim)
- 다익스트라(Dijkstra)

---

## 2.1 거스름돈 문제

동전의 개수를 최소화하기 위해 **가장 큰 액수의 동전부터 선택**한다.

단, 동전의 종류가 임의로 주어진 경우에는 항상 최적해를 보장하지 않는다.

예:

동전이 `1원, 3원, 4원`이고 6원을 만드는 경우

Greedy:

```text
4 + 1 + 1 = 3개
```

최적해:

```text
3 + 3 = 2개
```

---

## 2.2 분할 가능 배낭 문제

배낭의 용량을 초과하지 않으면서 물체들의 **이익의 합을 최대화**하는 문제이다.

물체를 쪼갤 수 있는 경우에는 다음 값을 기준으로 선택한다.

```text
단위 무게당 이익 = 이익 / 무게
```

즉,

> 이익/무게 값이 가장 큰 물체부터 넣는다.

# 3. 정렬의 분류

## 3.1 내부 정렬 / 외부 정렬

데이터가 저장되는 위치를 기준으로 구분한다.

### 내부 정렬

정렬할 데이터를 전부 **주기억장치(RAM)**에 올려서 정렬한다.

### 외부 정렬

데이터가 너무 커서 메모리에 전부 올릴 수 없는 경우 **보조기억장치(디스크 등)**를 사용한다.

---

## 3.2 비교 기반 정렬 / 데이터 분포 기반 정렬

### 비교 기반 정렬

두 데이터의 **키 값을 직접 비교**하여 순서를 결정한다.

대표 예:

- 선택 정렬
- 버블 정렬
- 삽입 정렬
- 셸 정렬
- 퀵 정렬
- 합병 정렬
- 힙 정렬

성능을 판단할 때 **키 값의 비교 횟수**가 중요하다.

### 데이터 분포 기반 정렬

입력값의 범위, 출현 횟수, 자릿수, 데이터 분포 등을 이용하여 정렬한다.

대표 예:

- 계수 정렬
- 기수 정렬
- 버킷 정렬

조건에 따라 **O(n)** 수준의 정렬도 가능하다.

---

## 3.3 안정적 정렬

같은 키 값을 가진 데이터들의 **상대적인 순서가 정렬 후에도 유지되는 정렬**이다.

예:

```text
정렬 전
3-A, 1, 3-B, 2

정렬 후
1, 2, 3-A, 3-B
```

`3-A`, `3-B`의 순서가 유지되었으므로 안정적이다.

---

## 3.4 제자리 정렬

입력 데이터의 크기가 증가해도 추가 저장공간 사용량이 입력 크기에 비례하여 증가하지 않는 정렬이다.

즉,

> 별도의 큰 배열을 만들지 않고 기존 저장공간을 주로 사용하는 방식

---

# 4. 선택 정렬(Selection Sort)

가장 작은 값을 찾아 **미정렬 부분의 맨 앞 데이터와 교환**한다.

과정:

1. 미정렬 부분에서 최솟값을 찾는다.
2. 최솟값과 미정렬 부분의 맨 앞 데이터를 교환한다.
3. 정렬된 부분을 한 칸 증가시킨다.
4. 반복한다.

특징:

- 입력 데이터의 초기 순서에 크게 민감하지 않음
- **제자리 정렬**
- **비안정적 정렬**
- 시간복잡도: **O(n²)**

핵심:

> 최솟값을 찾아 앞으로 보낸다.

---

# 5. 버블 정렬(Bubble Sort)

모든 **인접 데이터**를 차례대로 비교하고 필요하면 교환한다.

한 번의 반복이 끝나면 가장 큰 값 또는 가장 작은 값이 배열의 한쪽 끝에 자리 잡는다.

예:

```text
5 3 1 4

3 5 1 4
3 1 5 4
3 1 4 5
```

특징:

- **안정적 정렬**
- **제자리 정렬**
- 데이터 교환이 많이 발생
- 반복할수록 이미 정렬된 끝부분을 제외할 수 있음
- 시간복잡도: 일반적으로 **O(n²)**

핵심:

> 인접한 두 데이터를 계속 비교하고 교환한다.

---

# 6. 삽입 정렬(Insertion Sort)

데이터를 하나씩 뽑아서 이미 정렬된 부분의 **알맞은 위치에 삽입**한다.

배열을 다음처럼 생각한다.

```text
[정렬된 부분 | 미정렬 부분]
```

새로운 데이터를 하나 선택한 뒤 정렬된 부분에서 자기 위치를 찾아 삽입한다.

특징:

- **안정적 정렬**
- **제자리 정렬**
- 입력 데이터의 초기 순서에 민감
- 거의 정렬된 데이터에 효율적
- 최악 시간복잡도: **O(n²)**

핵심:

> 하나를 뽑아서 자기 자리에 삽입한다.

---

# 7. 셸 정렬(Shell Sort)

삽입 정렬의 단점을 개선한 정렬이다.

삽입 정렬은 멀리 떨어진 위치로 이동해야 할 때 한 칸씩 이동해야 한다.

셸 정렬은 일정한 간격인 `gap`을 두고 데이터를 묶은 뒤 삽입 정렬을 수행한다.

예:

```text
gap = 4
gap = 2
gap = 1
```

마지막에는 반드시 일반적인 삽입 정렬과 같은 형태가 된다.

순열값(gap)의 의미:

- 부분 배열에서 이웃한 데이터 간의 거리
- gap이 `h`라면 일반적으로 `h`개의 부분 배열이 만들어짐

특징:

- 삽입 정렬 개선
- 한 번에 먼 거리를 이동 가능
- 사용하는 gap 순열에 따라 성능이 달라짐
- **비안정적 정렬**
- **제자리 정렬**

---

# 8. 퀵 정렬(Quick Sort)

특정 데이터인 **피벗(Pivot)**을 기준으로 배열을 두 부분으로 나눈 뒤 각 부분 배열에 퀵 정렬을 재귀적으로 적용한다.

## 8.1 피벗(Pivot)

배열을 두 부분으로 분할하는 기준 데이터이다.

피벗은 보통 다음 중 하나를 선택한다.

- 첫 번째 데이터
- 마지막 데이터
- 가운데 데이터

오름차순 기준 최종 형태:

```text
[피벗보다 작은 값] Pivot [피벗보다 큰 값]
```

즉,

- 피벗보다 작은 값 → 왼쪽
- 피벗보다 큰 값 → 오른쪽

일반적인 양방향 분할에서는:

- `left`: 왼쪽에서 시작해서 **피벗보다 큰 값**을 찾음
- `right`: 오른쪽에서 시작해서 **피벗보다 작은 값**을 찾음

찾은 두 값을 서로 교환한다.

분할이 완료되면 피벗은 **최종적으로 자기 자리**를 잡는다.

## 8.2 분할 정복

### 분할
피벗 기준으로 배열을 두 부분으로 나눈다.

### 정복
왼쪽과 오른쪽 부분 배열에 퀵 정렬을 재귀적으로 적용한다.

### 결합
별도의 결합 과정이 없다.

```text
퀵 정렬
분할 O
정복 O
결합 X
```

## 8.3 수행시간

- 최선: **O(n log n)**
- 평균: **O(n log n)**
- 최악: **O(n²)**

피벗이 계속 최솟값 또는 최댓값으로 선택되면 한쪽으로 치우치므로 최악의 성능이 발생한다.

특징:

- 분할 정복
- **비안정적 정렬**
- 일반적인 구현은 **제자리 정렬**
- 피벗 선택이 성능에 큰 영향을 줌

---

# 9. 합병 정렬(Merge Sort)

배열을 계속 반으로 나눈 뒤 다시 **정렬하면서 합치는 방식**이다.

과정:

1. 배열을 동일하거나 거의 동일한 크기의 두 부분 배열로 나눈다.
2. 각 부분 배열에 합병 정렬을 재귀적으로 적용한다.
3. 정렬된 두 배열의 앞쪽 원소를 비교하면서 하나의 정렬된 배열로 합친다.

## 9.1 분할 정복

### 분할
배열을 절반씩 나눈다.

### 정복
각 부분 배열에 합병 정렬을 재귀적으로 적용한다.

### 결합
두 정렬된 부분 배열을 하나로 합친다.

```text
합병 정렬
분할 O
정복 O
결합 O
```

특징:

- **안정적 정렬**
- 일반적인 배열 구현에서는 **제자리 정렬이 아님**
- 시간복잡도: **O(n log n)**
- 입력 순서에 따른 성능 변화가 크지 않음
- 합병을 위한 추가 배열 필요

---

# 10. 힙(Heap)

힙은 **완전 이진 트리**이면서 힙 조건을 만족하는 자료구조이다.

## 10.1 완전 이진 트리

위에서부터 왼쪽부터 **빈자리 없이 채워지는 이진 트리**이다.

## 10.2 최대 힙 / 최소 힙

### 최대 힙(Max Heap)

모든 부모 노드가 자식 노드보다 **크거나 같다.**

```text
부모 >= 자식
```

따라서 루트에는 항상 **최댓값**이 위치한다.

### 최소 힙(Min Heap)

모든 부모 노드가 자식 노드보다 **작거나 같다.**

```text
부모 <= 자식
```

따라서 루트에는 항상 **최솟값**이 위치한다.

## 10.3 힙을 배열로 구현하는 이유

힙은 완전 이진 트리이므로 빈 공간 없이 **1차원 배열**로 효율적으로 저장할 수 있다.

0번 인덱스를 기준으로 할 경우:

```text
부모 인덱스 = i

왼쪽 자식 = 2i + 1
오른쪽 자식 = 2i + 2
부모 = floor((i - 1) / 2)
```

## 10.4 힙의 장점

### 삽입

새로운 데이터를 배열 마지막에 넣는다.

부모와 비교하면서 힙의 조건을 만족할 때까지 위로 이동한다.

시간복잡도:

**O(log n)**

### 삭제

최대 힙에서는 최댓값 삭제가 쉽다.

최소 힙에서는 최솟값 삭제가 쉽다.

과정:

1. 루트 데이터 제거
2. 마지막 데이터를 루트로 이동
3. 마지막 위치 삭제
4. 자식 노드와 비교하며 아래로 이동
5. 힙 재구성

시간복잡도:

**O(log n)**

---

# 11. 힙 정렬(Heap Sort)

힙 자료구조의 특성을 이용한 정렬이다.

오름차순:

> **최대 힙 사용**

내림차순:

> **최소 힙 사용**

## 11.1 힙 정렬 과정

1. 배열을 힙 구조로 변환
2. 루트의 최댓값 또는 최솟값을 정렬될 위치로 이동
3. 남은 데이터로 힙 재구성
4. 반복

## 11.2 초기 힙 구축

### 방법 1. 순차 삽입 방식

원소를 하나씩 넣으면서 부모와 비교하고 위로 올린다.

전체 힙 구축:

**O(n log n)**

### 방법 2. 일괄 구축 방식

배열 전체를 완전 이진 트리로 본다.

가장 아래쪽의 부모 노드부터 위쪽으로 `heapify`를 수행한다.

전체 힙 구축:

**O(n)**

## 11.3 힙 정렬 수행시간

- 최선: **O(n log n)**
- 평균: **O(n log n)**
- 최악: **O(n log n)**

이유:

```text
바깥 반복 ≈ n번
heapify ≈ log n

n × log n
= O(n log n)
```

특징:

- **비안정적 정렬**
- **제자리 정렬**
- 입력 데이터의 초기 순서에 따른 성능 변화가 크지 않음

---

# 12. 비교 기반 정렬의 하한

비교만을 이용하는 일반적인 정렬 알고리즘은 최악의 경우 최소

**Ω(n log n)**

수준의 비교가 필요하다.

주의:

```text
O = 상한
Ω = 하한
```

따라서 비교 기반 정렬에서 `O(n log n)`은 매우 효율적인 성능이다.

하지만 계수 정렬, 기수 정렬, 버킷 정렬 등의 **분포 기반 알고리즘**은 비교만을 사용하는 것이 아니기 때문에 이 제한을 직접 받지 않는다.

조건이 적절하면 **O(n)** 에 가까운 선형 시간도 가능하다.

---

# 13. 계수 정렬(Counting Sort)

각 데이터가 몇 번 등장했는지 **출현 횟수를 계산**하고, 누적 횟수를 이용하여 정렬 위치를 찾는다.

예:

```text
입력
2 5 3 2 3 1
```

출현 횟수:

```text
1 → 1개
2 → 2개
3 → 2개
4 → 0개
5 → 1개
```

누적 횟수:

```text
값        1 2 3 4 5
출현횟수   1 2 2 0 1
누적횟수   1 3 5 5 6
```

## 13.1 시간복잡도

입력 데이터 수가 `n`, 데이터 값의 범위가 `0 ~ k`라면

**O(n + k)**

## 13.2 사용하기 좋은 경우

- 입력값 범위 `k`가 작을 때
- `k`가 데이터 개수 `n`에 비례할 때
- 입력값의 범위를 미리 알 수 있을 때

특징:

- **안정적 정렬**
- 일반적인 구현에서는 **제자리 정렬 아님**
- 입력값의 범위가 너무 크면 메모리 낭비 발생
- 모든 데이터에 범용적으로 사용하기 어려움

---

# 14. 기수 정렬(Radix Sort)

입력값을 **자릿수별로 나누어 정렬**하는 방식이다.

## 14.1 LSD

Least Significant Digit

낮은 자리부터 정렬한다.

```text
일의 자리
→ 십의 자리
→ 백의 자리
```

## 14.2 MSD

Most Significant Digit

높은 자리부터 정렬한다.

```text
백의 자리
→ 십의 자리
→ 일의 자리
```

중요:

> 각 자릿수를 정렬할 때 안정적인 정렬 알고리즘을 사용해야 이전 자릿수 정렬 결과가 유지된다.

보통 계수 정렬을 사용한다.

특징:

- 분포 기반 정렬
- 안정적인 보조 정렬을 사용하면 **안정적**
- 일반적인 구현은 **제자리 정렬 아님**
- 자릿수 수와 각 자리 값의 범위에 따라 성능이 달라짐

---

# 15. 버킷 정렬(Bucket Sort)

데이터의 범위를 여러 구간인 **버킷(Bucket)**으로 나눈 뒤 각 데이터를 해당 버킷에 넣는다.

그 후 각 버킷 내부를 정렬하고 다시 이어 붙인다.

과정:

1. 여러 개의 버킷 생성
2. 데이터를 적절한 버킷에 분배
3. 각 버킷 내부 정렬
4. 버킷 순서대로 이어 붙임

보통 버킷 내부에서는 **삽입 정렬** 등을 사용할 수 있다.

## 15.1 좋은 조건

- 데이터가 값의 범위에서 **확률적으로 균등하게 분포**
- 버킷의 수가 데이터 수에 적절히 비례

이 경우 평균적으로 **O(n)** 수준의 성능이 가능하다.

하지만 한 버킷에 데이터가 몰리면 성능이 나빠질 수 있다.

특징:

- 일반적으로 **제자리 정렬 아님**
- 안정성은 버킷 내부 정렬 알고리즘과 구현에 따라 달라짐

---

# 4. 균형 탐색 트리와 해싱

## 4.1 레드-블랙 트리(Red-Black Tree)

레드-블랙 트리는 **이진 탐색 트리(BST)**의 한 종류이며, 트리가 한쪽으로 지나치게 치우치지 않도록 색상 규칙과 회전을 이용해 균형을 유지하는 **균형 탐색 트리**이다.

### 특징

- 이진 탐색 트리이므로 탐색 방식은 일반 BST와 동일하다.
- 각 노드는 **빨강(Red)** 또는 **검정(Black)** 중 하나의 색을 가진다.
- 노드에는 기존 BST 정보에 더해 색상 정보가 추가된다.
- 트리의 높이가 `O(log n)` 수준으로 유지된다.

### 레드-블랙 트리의 조건

1. 모든 노드는 빨강 또는 검정이다.
2. **루트 노드는 검정**이다.
3. 모든 NIL 리프 노드는 검정이다.
4. 빨강 노드의 자식은 반드시 검정이다.
   - 즉, 빨강 노드가 연속해서 나타날 수 없다.
5. 임의의 노드에서 그 아래의 모든 리프 노드까지 가는 경로에는 **동일한 개수의 검정 노드**가 존재한다.

```text
        10(B)
       /     \
    5(R)     20(R)
   /  \      /   \
 NIL  NIL  NIL   NIL
```

### 삽입

새로운 노드는 일반적으로 **빨강 노드**로 삽입한다.

삽입 후 레드-블랙 트리의 규칙이 깨지면 다음 방법으로 균형을 맞춘다.

- 색상 변경(Recoloring)
- 왼쪽 회전(Left Rotation)
- 오른쪽 회전(Right Rotation)

#### 부모와 삼촌 노드가 빨강인 경우

부모와 삼촌을 검정으로 바꾸고 조부모를 빨강으로 변경한다.

```text
부모   → 검정
삼촌   → 검정
조부모 → 빨강
```

#### 삼촌 노드가 검정인 경우

노드의 위치에 따라 `LL`, `LR`, `RL`, `RR` 형태를 판단하여 회전과 색상 변경을 수행한다.

### 균형 특성

가장 긴 루트→리프 경로의 길이는 가장 짧은 루트→리프 경로 길이의 **2배를 넘지 않는다.**

따라서 탐색·삽입·삭제의 시간 복잡도가 안정적으로 유지된다.

### 시간 복잡도

| 연산 | 시간 복잡도 |
|---|---:|
| 탐색 | `O(log n)` |
| 삽입 | `O(log n)` |
| 삭제 | `O(log n)` |

### 핵심

```text
레드-블랙 트리
→ 균형을 유지하는 이진 탐색 트리
→ 노드에 Red / Black 색상 정보 저장
→ 색상 변경 + 회전으로 균형 유지
→ 탐색·삽입·삭제 O(log n)
```

---

## 4.2 B-트리(B-Tree)

B-트리는 하나의 노드에 여러 개의 키를 저장할 수 있는 **균형 탐색 트리**이다.

이진 탐색 트리와 달리 하나의 노드가 여러 개의 자식 노드를 가질 수 있어 트리의 높이를 낮출 수 있다.

### 특징

- 하나의 노드에 여러 개의 키가 저장될 수 있다.
- 노드 내부의 키는 **오름차순으로 정렬**된다.
- 내부 노드가 키를 `k`개 가진다면 자식 노드는 `k + 1`개를 가진다.
- 모든 리프 노드의 레벨이 동일하다.
- 삽입 과정에서 노드가 가득 차면 **노드 분할(Node Split)**을 수행한다.
- 내부 탐색과 외부 탐색 모두에 활용된다.
- 데이터베이스 인덱스와 파일 시스템 등에 많이 사용된다.

### 최소 차수 t인 B-트리

최소 차수(Minimum Degree)를 `t`라고 하면 다음과 같다.

- 한 노드의 최대 키 개수: `2t - 1`
- 한 노드의 최대 자식 개수: `2t`
- 비어 있지 않은 루트 노드는 최소 1개의 키를 가진다.

### 키와 자식 관계

```text
        [10 | 20 | 30]
       /    |    |    \
     <10  10~20 20~30  >30
```

키가 3개이면 자식은 최대 4개가 된다.

```text
키 개수 = k
자식 개수 = k + 1
```

### 삽입과 노드 분할

노드가 가득 찬 상태에서 새로운 키를 삽입해야 하면 가운데 키를 부모 노드로 올리고 노드를 분할한다.

```text
[10 | 20 | 30]
```

분할:

```text
       [20]
      /    \
   [10]    [30]
```

이 과정을 통해 모든 리프 노드의 레벨을 동일하게 유지한다.

### 시간 복잡도

탐색·삽입·삭제는 일반적으로 다음과 같다.

```text
O(log n)
```

### 핵심

```text
B-트리
→ 균형 탐색 트리
→ 하나의 노드에 여러 키 저장
→ 키 k개이면 자식 k+1개
→ 모든 리프 노드의 레벨 동일
→ 삽입 시 가득 찬 노드는 분할
→ O(log n)
```

---

## 4.3 해싱(Hashing)

해싱은 **키(Key)를 기반으로 데이터의 저장 위치를 직접 계산**하는 방법이다.

```text
Key
 ↓
Hash Function
 ↓
Hash Address
 ↓
Hash Table
```

해시 테이블의 각각의 저장 위치를 **슬롯(Slot)**이라고 한다.

예를 들어 테이블 크기가 10일 때 다음과 같은 해시 함수를 사용할 수 있다.

```text
h(27) = 27 % 10
      = 7
```

따라서 데이터는 7번 슬롯에 저장된다.

### 평균 시간 복잡도

| 연산 | 평균 시간 복잡도 |
|---|---:|
| 탐색 | `O(1)` |
| 삽입 | `O(1)` |
| 삭제 | `O(1)` |

단, 서로 다른 키가 같은 해시 주소를 가지면 **충돌(Collision)**이 발생한다.

---

## 4.4 해시 함수(Hash Function)

해시 함수는 키를 입력받아 해시 테이블의 저장 위치를 계산하는 함수이다.

```text
Key → Hash Address
```

### 1) 제산 잔여법

키를 해시 테이블의 크기로 나눈 **나머지**를 사용한다.

```text
h(k) = k mod m
```

예:

```text
key = 123
m = 10

123 % 10 = 3
```

따라서 3번 슬롯에 저장한다.

### 2) 비닝(Binning)

전체 키 공간 `U`를 해시 테이블 크기 `M`에 맞추어 여러 구간으로 나누고 각 구간을 하나의 슬롯에 대응시키는 방법이다.

```text
0~99      → 슬롯 0
100~199   → 슬롯 1
200~299   → 슬롯 2
...
```

### 3) 중간 제곱법(Mid-Square Method)

키 값을 제곱한 뒤 결과의 **중간 부분의 숫자 또는 비트**를 추출하여 해시 주소로 사용한다.

```text
key = 123

123² = 15129

중간 부분 추출 → 512 등
```

### 문자열을 위한 해싱

#### 문자열 앞부분 사용

문자열의 앞쪽 일부를 이용하여 해시 값을 만드는 방법이다.

단, 앞부분이 비슷한 문자열이 많으면 충돌이 증가할 수 있다.

#### 문자 코드값의 합 사용

각 문자의 코드값을 더한 뒤 제산 잔여법 등을 적용한다.

```text
ABC

A = 65
B = 66
C = 67

65 + 66 + 67 = 198

198 % tableSize
```

---

## 4.5 충돌(Collision)

서로 다른 키가 같은 해시 주소로 계산되는 현상을 **충돌**이라고 한다.

```text
h(key1) = 5
h(key2) = 5
```

대표적인 충돌 해결 방법은 다음 두 가지이다.

```text
충돌 해결
   │
   ├─ 개방 해싱(Open Hashing)
   │    └─ 체이닝(Chaining)
   │
   └─ 폐쇄 해싱(Closed Hashing)
        └─ 개방 주소법(Open Addressing)
             ├─ 선형 탐사
             ├─ 이차 탐사
             └─ 이중 해싱
```

---

## 4.6 개방 해싱(Open Hashing)

개방 해싱의 대표적인 방법은 **체이닝(Chaining)**이다.

해시 테이블의 각 슬롯을 연결 리스트의 헤더처럼 사용하고, 충돌한 데이터는 연결 리스트로 연결하여 저장한다.

```text
Hash Table

0
1
2 → [12] → [22] → [32]
3
4
```

예:

```text
12 % 10 = 2
22 % 10 = 2
32 % 10 = 2
```

모두 2번 슬롯에 대응하지만 연결 리스트로 관리한다.

### 핵심

```text
개방 해싱
→ 체이닝
→ 각 슬롯을 연결 리스트의 헤더처럼 사용
→ 충돌 데이터를 연결 구조로 저장
```

---

## 4.7 폐쇄 해싱(Closed Hashing)

폐쇄 해싱은 충돌한 데이터를 **해시 테이블 내부의 다른 빈 슬롯**에 저장하는 방식이다.

대표적으로 **개방 주소법(Open Addressing)**을 사용한다.

```text
5번 슬롯 → 이미 사용 중
6번 슬롯 → 비어 있음

→ 6번 슬롯에 저장
```

대표적인 탐사 방법:

- 선형 탐사(Linear Probing)
- 이차 탐사(Quadratic Probing)
- 이중 해싱(Double Hashing)

### 버킷을 이용하는 방법

여러 슬롯을 하나의 버킷으로 묶어 관리하고, 버킷이 가득 찬 경우 별도의 오버플로 영역을 이용하는 방식도 있다.

---

## 4.8 선형 탐사(Linear Probing)

충돌이 발생하면 **다음 슬롯을 순서대로 확인**하여 빈 공간을 찾는다.

```text
h(k)
h(k) + 1
h(k) + 2
h(k) + 3
...
```

예:

```text
5 → 사용 중
6 → 사용 중
7 → 비어 있음

→ 7에 저장
```

### 단점

연속된 영역에 데이터가 몰리는 **1차 군집화(Primary Clustering)** 현상이 발생할 수 있다.

---

## 4.9 이차 탐사(Quadratic Probing)

충돌이 발생했을 때 탐색 간격을 제곱 형태로 증가시킨다.

```text
h(k) + 1²
h(k) + 2²
h(k) + 3²
...
```

예:

```text
기본 위치 = 5

5 + 1² = 6
5 + 2² = 9
5 + 3² = 14
```

선형 탐사의 군집화 문제를 어느 정도 완화할 수 있다.

---

## 4.10 시험용 핵심 정리

| 자료구조 / 방법 | 핵심 |
|---|---|
| 이진 탐색 트리 | `왼쪽 < 부모 < 오른쪽` |
| 레드-블랙 트리 | 색상 규칙과 회전으로 균형을 유지하는 BST |
| B-트리 | 한 노드에 여러 키를 저장하는 균형 탐색 트리 |
| 해싱 | 키를 이용해 저장 위치를 직접 계산 |
| 충돌 | 서로 다른 키가 같은 해시 주소를 가지는 현상 |
| 개방 해싱 | 체이닝, 연결 리스트 이용 |
| 폐쇄 해싱 | 해시 테이블 내부의 다른 슬롯 이용 |
| 선형 탐사 | 다음 슬롯부터 순차 탐색 |
| 이차 탐사 | `1², 2², 3² ...` 간격으로 탐색 |

```text
레드-블랙 트리
→ O(log n)

B-트리
→ 모든 리프 노드의 레벨 동일
→ O(log n)

해싱
→ 평균 O(1)

개방 해싱
→ 체이닝

폐쇄 해싱
→ 개방 주소법
→ 선형 탐사 / 이차 탐사 / 이중 해싱
```

# 5. 그래프(Graph)

그래프는 **정점(Vertex)**과 **간선(Edge)**의 집합으로 구성된다.

```text
G = (V, E)
```

- `V(Vertex)` : 정점의 집합
- `E(Edge)` : 간선의 집합

## 5.1 그래프의 종류

### 방향에 따른 구분

- **무방향 그래프(Undirected Graph)**
  - 간선에 방향이 없다.
  - 두 정점이 연결되어 있으면 양쪽으로 이동할 수 있다.

- **방향 그래프(Directed Graph)**
  - 간선에 방향이 존재한다.
  - `A → B`와 `B → A`는 서로 다른 간선이다.

### 가중치에 따른 구분

- **가중 그래프(Weighted Graph)**
  - 간선에 거리, 비용, 시간 등의 값을 저장한다.
  - 이 값을 **가중치(Weight)**라고 한다.

---

## 5.2 트리와 그래프의 관계

트리는 그래프 중에서 다음 조건을 만족하는 특수한 그래프이다.

1. **무방향 그래프**이다.
2. **모든 정점이 서로 연결**되어 있다.
3. **사이클(Cycle)이 존재하지 않는다.**

즉,

```text
트리 = 연결된 무방향 그래프 + 사이클 없음
```

정점이 `n`개인 트리의 간선 개수는 항상 다음과 같다.

```text
n - 1
```

---

## 5.3 그래프의 구현

그래프를 컴퓨터에서 표현하는 대표적인 방법은 다음 두 가지이다.

- 인접 행렬
- 인접 리스트

### 인접 행렬(Adjacency Matrix)

그래프를 **2차원 배열**로 표현한다.

일반 그래프에서는 보통 다음과 같이 표현한다.

- 간선이 존재하면 `1`
- 간선이 존재하지 않으면 `0`
- 자기 자신으로 가는 간선이 없다면 대각선은 `0`

예:

|   | A | B | C |
|---|---:|---:|---:|
| A | 0 | 1 | 0 |
| B | 1 | 0 | 1 |
| C | 0 | 1 | 0 |

가중 그래프에서는 간선이 존재하면 해당 **가중치**를 저장한다.

최단 경로 문제 등에서는 연결되지 않은 정점 사이의 값을 보통 `∞`로 표현한다.

예:

|   | A | B | C |
|---|---:|---:|---:|
| A | 0 | 5 | ∞ |
| B | 5 | 0 | 3 |
| C | ∞ | 3 | 0 |

> 일반 인접 행렬에서는 간선 없음 = `0`, 가중 그래프의 최단 경로 표현에서는 간선 없음 = `∞`로 사용하는 경우가 많다.

### 인접 리스트(Adjacency List)

각 정점과 연결된 정점들을 **리스트 형태**로 표현한다.

예:

```text
A → B → C
B → A → D
C → A
D → B
```

연결 리스트나 배열/List 자료구조 등을 이용해 구현할 수 있다.

가중 그래프라면 정점과 함께 가중치도 저장한다.

```text
A → (B, 5) → (C, 3)
```

간선의 수가 적은 **희소 그래프**에서는 인접 행렬보다 메모리를 효율적으로 사용할 수 있다.

---

## 5.4 그래프 순회(Graph Traversal)

그래프 순회란

> 그래프의 모든 정점을 체계적인 방법으로 방문하는 것

이다.

대표적인 그래프 순회 방법은 다음과 같다.

- 깊이 우선 탐색(DFS)
- 너비 우선 탐색(BFS)

### 정점의 구분

- **방문 정점** : 이미 방문이 완료된 정점
- **주변 정점** : 현재 방문한 정점과 인접해 있으면서 아직 방문하지 않은 정점
- **미도달 정점** : 현재까지 탐색 과정에서 아직 접근하지 못한 정점

---

## 5.5 깊이 우선 탐색(DFS)

**DFS(Depth First Search)**는 한 방향으로 가능한 깊게 탐색한 뒤 더 이상 이동할 수 없으면 이전 정점으로 돌아가는 탐색 방법이다.

### 특징

- 최근에 발견한 주변 정점을 우선 방문한다.
- 한 정점에서 인접한 정점 하나를 선택하여 계속 깊게 이동한다.
- 더 이상 이동할 정점이 없으면 이전 정점으로 되돌아간다.
- **스택(Stack)** 구조를 사용한다.
- 재귀 함수로도 구현할 수 있다.

### 수행 과정

1. 시작 정점을 방문하고 스택에 삽입한다.
2. 스택의 `top` 정점에서 방문하지 않은 인접 정점을 찾는다.
3. 인접 정점이 존재하면 해당 정점을 방문하고 스택에 `push`한다.
4. 방문하지 않은 인접 정점이 없다면 현재 정점을 `pop`하여 이전 정점으로 돌아간다.
5. 스택이 빌 때까지 반복한다.

예:

```text
A
├─ B
│  └─ D
└─ C
```

탐색 순서의 한 예:

```text
A → B → D → C
```

### 깊이 우선 트리(DFS Tree)

DFS를 수행하면서

- 방문한 정점
- 정점을 방문할 때 사용된 간선

으로 구성된 트리를 **깊이 우선 탐색 트리**라고 한다.

---

## 5.6 너비 우선 탐색(BFS)

**BFS(Breadth First Search)**는 시작 정점에서 가까운 정점부터 차례대로 탐색하는 방법이다.

### 특징

- 먼저 발견한 주변 정점을 먼저 방문한다.
- 시작 정점에서 거리가 가까운 정점을 우선 탐색한다.
- 거리가 점점 멀어지는 순서로 탐색한다.
- **큐(Queue)**를 이용하여 주변 정점을 관리한다.

### 수행 과정

1. 시작 정점을 방문하고 큐에 삽입한다.
2. 큐에서 정점 하나를 꺼낸다.
3. 해당 정점의 방문하지 않은 모든 인접 정점을 방문한다.
4. 방문한 인접 정점들을 큐에 삽입한다.
5. 큐가 빌 때까지 반복한다.

예:

```text
        A
      /   \
     B     C
    / \   /
   D   E F
```

BFS 탐색 순서:

```text
A → B → C → D → E → F
```

즉, 같은 거리의 정점들을 먼저 모두 방문한다.

---

## 5.7 DFS와 BFS 비교

| 구분 | DFS | BFS |
|---|---|---|
| 의미 | 깊이 우선 탐색 | 너비 우선 탐색 |
| 자료구조 | 스택 | 큐 |
| 탐색 방법 | 한 방향으로 깊게 | 가까운 정점부터 |
| 특징 | 막히면 이전 정점으로 되돌아감 | 같은 깊이의 정점을 먼저 방문 |

시험에서 가장 중요한 구분은 다음과 같다.

```text
DFS → Stack → 깊게
BFS → Queue → 가까운 곳부터
```

## 5.8 위상 정렬(Topological Sort)

위상 정렬은

> 방향 비순환 그래프(DAG)의 정점들을 모든 간선의 방향 관계를 만족하도록 한 줄로 나열하는 것

이다.

### 조건

위상 정렬은 반드시 **DAG(Directed Acyclic Graph)**에서만 가능하다.

즉,

- 방향 그래프여야 한다.
- 사이클이 없어야 한다.

예:

```text
A → B → D
└→ C → D
```

가능한 위상 정렬 결과의 예:

```text
A → B → C → D
```

또는

```text
A → C → B → D
```

처럼 그래프 구조에 따라 여러 정렬 결과가 존재할 수 있다.

### DFS를 이용한 위상 정렬

DFS 수행 중 한 정점의 탐색이 완전히 끝나는 시점에 해당 정점을 스택에 저장한다.

모든 DFS가 종료된 뒤 **스택에서 꺼내는 순서**, 즉 DFS 종료 순서의 역순으로 정점을 나열하면 위상 정렬 결과를 얻을 수 있다.

```text
DFS 종료 순서의 역순
→ 위상 정렬 결과
```

---

## 5.9 연결 성분(Connected Component)

연결 성분은

> 무방향 그래프에서 모든 정점 사이에 경로가 존재하는 최대 부분 그래프

이다.

예:

```text
A — B — C

D — E
```

연결 성분은 다음 2개이다.

```text
{A, B, C}
{D, E}
```

DFS 또는 BFS를 이용하여 구할 수 있다.

---

## 5.10 강연결 성분(SCC)

**강연결 성분(Strongly Connected Component)**은

> 방향 그래프에서 임의의 두 정점 사이에 서로 왕복할 수 있는 경로가 존재하는 최대 부분 그래프

이다.

정점 `A`, `B`가 같은 강연결 성분에 속하려면 다음 경로가 모두 존재해야 한다.

```text
A → ... → B
B → ... → A
```

예:

```text
A → B
↑   ↓
└─ C
```

A, B, C가 서로에게 모두 도달할 수 있다면

```text
{A, B, C}
```

가 하나의 강연결 성분이다.

---

## 5.11 시험용 핵심 정리

| 개념 | 핵심 |
|---|---|
| 그래프 | `G = (V, E)` |
| V | 정점(Vertex)의 집합 |
| E | 간선(Edge)의 집합 |
| 트리 | 연결된 무방향 그래프 + 사이클 없음 |
| 인접 행렬 | 2차원 배열로 표현 |
| 인접 리스트 | 각 정점의 인접 정점을 리스트로 표현 |
| DFS | 스택 사용, 한 방향으로 깊게 탐색 |
| BFS | 큐 사용, 가까운 정점부터 탐색 |
| 위상 정렬 | DAG에서만 가능 |
| 연결 성분 | 무방향 그래프의 연결된 최대 부분 그래프 |
| 강연결 성분 | 방향 그래프에서 서로 왕복 가능한 최대 부분 그래프 |

```text
그래프 G = (V, E)
V = 정점
E = 간선

트리
→ 무방향
→ 모든 정점 연결
→ 사이클 없음

DFS
→ Stack
→ 깊게 탐색

BFS
→ Queue
→ 가까운 정점부터 탐색

위상 정렬
→ DAG에서만 가능
→ DFS 종료 순서의 역순 이용 가능

연결 성분
→ 무방향 그래프

강연결 성분
→ 방향 그래프
→ 양방향 도달 가능
```
