# 일기장 기능 구현 계획

기준: `docs/diary-next-design.md`. 현재 디자인 브랜치에서 이어서 구현한다.

- [ ] 검증 유틸리티: 실제 날짜·기분·사진 제한·커서 형식을 Node 테스트로 검증한다.
- [ ] API: 작성자 식별, 소유권 조건부 수정/삭제, 수정 시각 충돌 검사, 검색과 커서 페이지 나누기, 월간 캘린더를 구현한다.
- [ ] 임시 저장: 작성자별 초안 테이블과 버전 조건부 저장/삭제 API, 생성 경쟁 및 다중 탭 충돌 처리를 추가한다.
- [ ] 작성 UI: 공용 작성/수정 폼, 사진 미리보기·삭제·교체, 초안 복원/버리기·2초 자동 저장·실패 상태를 연결한다.
- [ ] 조회 UI: URL 검색·필터, 날짜별 다건 일기, 월간 통계·기분 분포, 본인 수정/삭제 버튼을 연결한다.
- [ ] 검증: Node 테스트, lint, build, 브라우저 모바일/데스크톱 렌더링을 확인한다. 실제 DB 미설정 한계와 마이그레이션 적용 필요 여부를 기록한다.

신규 데이터 구조는 `0011_diary_features.sql`에 작성한다. 기존 사진은 수정 시 보존하고 사용자가 명시적으로 제거한 사진만 저장 성공 후 정리한다. 본문은 로컬 저장소에 보관하지 않는다. 새로운 의존성은 필요할 때만 추가한다.
